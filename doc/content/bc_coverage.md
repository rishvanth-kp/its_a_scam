# bc_coverage


## Description
`bc_coverage` computes the genome-wide read coverage (depth) of each
cell. Each alignment is processed separately (the two reads of a pair
are not combined into a fragment), and the bases that are aligned to the
reference (CIGAR operations M, =, and X) are added to the coverage of
its cell. Deletions, skipped regions (such as splice junctions),
insertions, and clipped bases do not add coverage. If the two reads of a
pair overlap, the overlapping bases are counted twice. To compute the
fragment coverage of single cell ATAC-seq data, see
[`bc_fragment_coverage`](bc_fragment_coverage.md).

## Parameters
```
bc_coverage [options]
	-a aligned SAM/BAM file [required]
	-b barcode list [required]
	-o outfile prefix [required]
	-d name split delimiter [default: ":"; ignored if -t is provided]
	-c barcode field in name [default: 7 (0 based); ignored if -t is provided]
	-q minimum mapping quality to include [default: 0]
	-f only include if all the flags are present [default: 3]
	-F only include if none of the flags are present [default: 3340]
	-v verbose [default: false]
```

`-a`: The input aligned SAM or BAM file. The cell barcode should be
present either in a SAM tag or encoded in the query name (QNAME) field,
see options `-t`, `-d`, and `-c`. [Required].

`-b`: Only the SAM/BAM entries that match a barcode in this file are
processed, and the coverage is computed separately for each barcode.
[Required].

`-o`: Output file prefix. [Required].

`-d`: Used when the cell barcode is encoded as a part of the query name
(QNAME field). Split the QNAME by the specified delimiter. [Default:
":"].

`-c`: Used when the cell barcode is encoded as a part of the query name
(QNAME field). Split the QNAME by the delimiter specified by `-d`
and take the barcode as the value in the column specified by `-c` (0
based). For example, reads that are generated by Illumina sequencers
have FASTQ names with 7 fields that are separated by a ":", and
the cell barcode is typically added as the 8th field. The column must
exist in the QNAME of every read; this is not checked. [Default: 7].

`-t` (not listed in the help text): Used when the cell barcode is
present in a SAM entry as a tag. For example, SAM files generated by
CellRanger or STARsolo encode the error-corrected cell barcode in the
`CB` tag. If this parameter is set, `-d` and `-c` flags are ignored.
[Default: none].

`-q`: Include only alignments that have a mapping quality greater than
or equal to the specified value. [Default: 0].

`-f`: Include only alignments that have all of the specified flags
present. For example, to include paired reads (0x1, decimal 1) and reads
that are mapped in proper pair (0x2, decimal 2), specify the sum of these
flags (1 + 2 = 3). The default includes only paired reads, so `-f` must
be set to 0 for single-end data, such as the BAM files generated by
STARsolo (for example, `-t CB -f 0`). [Default: 3].

`-F`: Include only alignments that have none of the specified flags
present. For example, to exclude PCR duplicates (0x400, decimal 1024)
and supplementary alignments (0x800, decimal 2048), specify the sum of
these flags (1024 + 2048 = 3072). The default (4 + 8 + 256 + 1024 + 2048
= 3340) excludes alignments that are unmapped (0x4), have an unmapped
mate (0x8), are secondary alignments (0x100), are PCR duplicates
(0x400), or are supplementary alignments (0x800). [Default: 3340].

`-v`: Verbosity flag. Set the flag to print progress and statistics to
standard error. [Default: false].

## Input and output file description
### Description of input files
1. A single- or paired-end aligned SAM/BAM file that has a cell barcode
encoded either in the query name or in a tag.
2. An uncompressed TSV file with the cell barcodes in the first column
(for example, the output of [`barcode_count`](barcode_count.md)). The
barcodes must be unique; this is not checked.

### Description of output files
1. `<output_prefix>_bc_depth.txt`: The coverage of each cell. The first
3 columns contain the chromosome name, start, and end of each region
(0-based start, and the end is not included), and the subsequent columns
are the cells, in the same order as the barcode list. Each value is the
number of alignments of the cell that cover the region. Only the
positions that are covered by at least one included alignment are
listed, and adjacent positions that have the same coverage are merged
into a single region. This file has a header line with the column names
`chrom`, `start`, and `end`, followed by the cell barcodes.
