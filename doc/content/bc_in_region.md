# bc_in_region


## Description
`bc_in_region` counts, for each cell, the number of fragments and the
number of fragments that overlap a set of regions of interest. This can
be used to compute per-cell metrics for single cell ATAC-seq data, such
as the fraction of fragments in peaks or in transcription start site
regions. A fragment is counted as in a region if it overlaps at least one
region in the bed file (`-r`) by at least one base.

## Parameters
```
bc_in_region [options]
  -a aligned SAM/BAM file [required]
  -b barcode list file [required]
  -r regions bed file [required]
  -s distance to add to either side of each region [default: 0]
  -o out file prefix [required]
  -d name split delimiter [default: ":"]
  -c barcode field in name [default: 7 (0 based)]
  -q minimum mapping quality to include [default: 0]
  -f only include if all the flags are present [default: 3]
  -F only include if none of the flags are present [default: 3340]
  -v verbose [default: false]
```

`-a`: The input aligned paired-end SAM or BAM file. The cell barcode
should be encoded in the query name (QNAME) field, see options `-d` and
`-c`. [Required].

`-b`: Only the SAM/BAM entries that match a barcode in this file are
processed. [Required].

`-r`: A bed file with the regions of interest. [Required].

`-s`: Number of bases to add to the ends of each region in the above bed
file. This parameter is useful to include the fragments flanking a
region of interest. `-s` must not be larger than the start of any
region; this is not checked. [Default: 0].

`-o`: Output file prefix. [Required].

`-d`: Split the QNAME by the specified delimiter. [Default: ":"].

`-c`: Split the QNAME by the delimiter specified by `-d` and take the
barcode as the value in the column specified by `-c` (0 based). For
example, reads that are generated by Illumina sequencers have FASTQ
names with 7 fields that are separated by a ":", and the cell
barcode is typically added as the 8th field. The column must exist in
the QNAME of every read; this is not checked. [Default: 7].

`-q`: Include only fragments for which both reads have a mapping
quality greater than or equal to the specified value. [Default: 0].

`-f`: Include only fragments for which both reads have all of the
specified flags present. For example, to include paired reads (0x1,
decimal 1) and reads that are mapped in proper pair (0x2, decimal 2),
specify the sum of these flags (1 + 2 = 3). [Default: 3].

`-F`: Include only fragments for which both reads have none of the
specified flags present. For example, to exclude PCR duplicates (0x400,
decimal 1024) and supplementary alignments (0x800, decimal 2048), specify
the sum of these flags (1024 + 2048 = 3072). The default (4 + 8 + 256 +
1024 + 2048 = 3340) excludes fragments in which either read is unmapped
(0x4), has an unmapped mate (0x8), is a secondary alignment (0x100), is a
PCR duplicate (0x400), or is a supplementary alignment (0x800).
[Default: 3340].

`-v`: Verbosity flag. Set the flag to print progress to standard error.
[Default: false].

## Input and output file description
### Description of input files
1. A paired-end aligned SAM/BAM file that has a cell barcode encoded
in the query name. The two reads of a fragment are paired by their query
name, so the file should contain only one alignment for each read.
Secondary and supplementary alignments, which have the same query name
as the read, should be removed beforehand (for example, with
`samtools view -F 2304`); the `-F` filter is applied only after the
reads have been paired.
2. A bed file (the first 3 columns are used) that contains the regions
of interest.
3. An uncompressed TSV file with the cell barcodes in the first column
(for example, the output of [`barcode_count`](barcode_count.md)).

### Description of output files
1. `<output_prefix>.txt`: A 3-column tab-separated file without a header.
The first column contains the cell barcode, the second column contains
the number of fragments of the cell that pass the filters, and the third
column contains the number of these fragments that overlap a region.
Every barcode in the barcode list is included, even if it has no
fragments. The rows are in no particular order.
