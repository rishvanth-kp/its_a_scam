# bc_tss_enrichment


## Description
`bc_tss_enrichment` computes the fragment coverage around transcription
start sites (TSSs) for each cell, which is used to determine the TSS
enrichment of single cell ATAC-seq data. For each cell, every base of
every fragment that falls within the distance specified by `-s` of a TSS
is counted at its position relative to the TSS, and the counts are
summed over all the TSSs. The positions are relative to the strand of
each TSS. If a barcode list is not provided (`-b`), all the fragments are
treated as a single (bulk) sample.

The coverage is normalized by the sum of the coverage in the 100
positions at each end of the window around the TSS. The TSS enrichment
score of a cell is typically the maximum of its normalized coverage. The
script
[`atacTssEnrichment.R`](https://github.com/rishvanth-kp/its_a_scam/blob/main/scripts/atacTssEnrichment.R)
plots the normalized coverage and the TSS enrichment scores.

## Parameters
```
bc_tss_enrichment [options]
	-a aligned SAM/BAM file [required]
	-r TSS region bed file [required]
	-s side distance to add to the ends of the TSS [default: 1000]
	-b barcode list (if empty, treated as bulk sample)
	-o outfile prefix [required]
	-n min fragment length [default: 1]
	-x max fragment length [default: 1000]
	-d name split delimiter [default: ":"; ignored if -t is provided]
	-c barcode field in name [default: 7 (0 based); ignored if -t is provided]
	-t barcode tag in SAM/BAM file [default ""]
	-q minimum mapping quality to include [default: 0]
	-f only include if all the flags are present [default: 3]
	-F only include if none of the flags are present [default: 3340]
	-v verbose [default: false]
```

`-a`: The input aligned paired-end SAM or BAM file. The cell barcode
should be present either in a SAM tag or encoded in the query name
(QNAME) field, see options `-t`, `-d`, and `-c`. [Required].

`-r`: A bed file with the TSSs. The name of each TSS is in the 4th column,
and the strand is in the 6th column (see below). [Required].

`-s`: Number of bases on either side of each TSS for which the coverage
is computed. The output contains 2 x `-s` + 1 positions. `-s` must be at
least 100, since the 100 positions at each end are used for
normalization, and must not be larger than the start of any TSS; this is
not checked. [Default: 1000].

`-b`: Only the SAM/BAM entries that match a barcode in this file are
processed, and the coverage is computed separately for each barcode. If
this parameter is not set, all the entries are treated as a single
sample. [Default: none].

`-o`: Output file prefix. If `-b` is not set, the prefix is also used as
the name of the sample. [Required].

`-n`: Minimum fragment length to include. Fragments that have a length
lower than this value are ignored. The fragment length is the distance
between the outermost alignment positions of the two reads.
[Default: 1].

`-x`: Maximum fragment length to include. Fragments that have a length
higher than this value are ignored. [Default: 1000].

`-d`: Used when the cell barcode is encoded as a part of the query name
(QNAME field). Split the QNAME by the specified delimiter. [Default:
":"].

`-c`: Used when the cell barcode is encoded as a part of the query name
(QNAME field). Split the QNAME by the delimiter specified by `-d`
and take the barcode as the value in the column specified by `-c` (0
based). For example, reads that are generated by Illumina sequencers
have FASTQ names with 7 fields that are separated by a ":", and
the cell barcode is typically added as the 8th field. Reads that do not
have this column are ignored. [Default: 7].

`-t`: Used when the cell barcode is present in a SAM entry as a tag. For
example, SAM files generated by CellRanger encode the error-corrected
cell barcode in the `CB` tag. If this parameter is set, `-d` and `-c`
flags are ignored. [Default: none].

`-q`: Include only fragments for which both reads have a mapping
quality greater than or equal to the specified value. [Default: 0].

`-f`: Include only fragments for which both reads have all of the
specified flags present. For example, to include paired reads (0x1,
decimal 1) and reads that are mapped in proper pair (0x2, decimal 2),
specify the sum of these flags (1 + 2 = 3). [Default: 3].

`-F`: Include only fragments for which both reads have none of the
specified flags present. For example, to exclude PCR duplicates (0x400,
decimal 1024) and supplementary alignments (0x800, decimal 2048), specify
the sum of these flags (1024 + 2048 = 3072). The default (4 + 8 + 256 +
1024 + 2048 = 3340) excludes fragments in which either read is unmapped
(0x4), has an unmapped mate (0x8), is a secondary alignment (0x100), is a
PCR duplicate (0x400), or is a supplementary alignment (0x800).
[Default: 3340].

`-v`: Verbosity flag. Set the flag to print progress and statistics to
standard error. [Default: false].

## Input and output file description
### Description of input files
1. A paired-end aligned SAM/BAM file that has a cell barcode encoded
either in the query name or in a tag. The two reads of a fragment are
paired by their query name, so the file should contain only one
alignment for each read. Secondary and supplementary alignments, which
have the same query name as the read, should be removed beforehand (for
example, with `samtools view -F 2304`); the `-F` filter is applied only
after the reads have been paired.
2. A 6-column bed file with the TSSs. The 4th column contains a unique
name for each TSS (this is not checked), and the 6th column contains the
strand (`+` or `-`). The positions around the TSSs on the `-` strand are
reversed, so that the upstream positions are always on the left.
3. Optionally, an uncompressed TSV file with the cell barcodes in the
first column (for example, the output of
[`barcode_count`](barcode_count.md)).

### Description of output files
The rows of the output files are the cells, in the same order as the
barcode list (or a single row named after `-o` for a bulk sample), and
the first column contains the cell barcode. Each file has a header line.

1. `<output_prefix>_tss_raw_counts.txt`: The subsequent columns are the
positions around the TSS: the column `i` (0 to 2 x `-s`) is at a
distance of `i` - `-s` from the TSS, so the TSS itself is in the column
`-s`. Each value is the coverage at the position, i.e., the number of
fragment bases at the position, summed over all the TSSs.
2. `<output_prefix>_tss_norm_factor.txt`: The second column contains the
normalization factor of each cell, which is the sum of the coverage at
the 100 positions at each end (the columns 0 to 99, and the last 100
columns of the above file).
3. `<output_prefix>_tss_enrichmet.txt`: Same as the raw counts file, but
with the coverage normalized by the normalization factor. If the
normalization factor of a cell is 0, all the values are 0.
