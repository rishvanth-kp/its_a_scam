# bc_atac_genomic_features

## Description
`bc_atac_genomic_features` is used to determine the fraction of fragments
aligned to different genomic regions at the single cell level. In a
typical ATAC-seq experiment, we would expect a lot of reads aligning to
the open chromatin regions that are mostly located in TSS and gene
body regions. This program determines the number of fragments and the
mean fragment length of fragments aligned to distinct genomic regions.

The genomic regions are obtained from the GTF file (`-g`): `CDS`, `UTR`,
`intron` (gene bodies outside of the CDS and UTR regions), and
`intergene` (outside of genes). All fragments that align to `chrM` are
assigned to `chrM`. Transcription start regions (`TSR`) and enhancers
(`enhancer`) are added if the corresponding bed files are provided (`-r`
and `-e`). Each fragment is first shifted (see `-s` and `-S`), and is
then counted in every region that contains the start of the fragment.
Therefore, a fragment can be counted in more than one region if the
regions overlap (for example, a TSR and a UTR).

## Parameters
```
bc_atac_genomic_features [options]
	-a aligned SAM/BAM file [required]
	-b barcode list file [required]
	-g gtf file [required]
	-r tsr bed file [optional]
	-e enhancers bed file [optional]
	-o out file prefix [required]
	-s Number of bases to shift left [default: 4]
	-S Number of bases to shift right [default: -5]
	-m min fragment length [default: 0]
	-M max fragment length [default: inf]
	-d name split delimiter [default: ":"; ignored if -t is provided]
	-c barcode field in name [default: 7 (0 based); ignored if -t is provided]
	-t barcode tag in SAM/BAM file [default ""]
	-q minimum mapping quality to include [default: 0]
	-f only include if all the flags are present [default: 3]
	-F only include if none of the flags are present [default: 3340]
	-v verbose [default: false]
```

`-a`: The input aligned paired-end SAM or BAM file. The cell barcode
should be present either in a SAM tag or encoded in the query name
(QNAME) field, see options `-t`, `-d`, and `-c`. [Required].

`-b`: Only the SAM/BAM entries that match a barcode in this file are
processed. [Required].

`-g`: GTF file that is used to parse the gene regions. [Required].

`-r`: A bed-3 file with transcription start regions. If this bed file is
provided, the fragments in the TSRs are counted. [Optional].

`-e`: A bed-3 file with enhancer regions. If this bed file is provided,
the fragments in the enhancer regions are counted. [Optional].

`-o`: Output file prefix. [Required].

`-s`: Number of bases to add to the leftmost alignment location of
each fragment to account for the Tn5 transposase cuts. The shift is
applied before the fragment length and the genomic regions of a fragment
are determined. [Default: 4].

`-S`: Number of bases to add to the rightmost alignment location of
each fragment to account for the Tn5 transposase cuts. [Default: -5].

`-m`: Minimum fragment length to include. Fragments that have a length
(after the shift) lower than this value are ignored. [Default: 0].

`-M`: Maximum fragment length to include. Fragments that have a length
(after the shift) higher than this value are ignored. [Default: inf,
i.e., no maximum].

`-d`: Used when the cell barcode is encoded as a part of the query name
(QNAME field). Split the QNAME by the specified delimiter. [Default:
":"].

`-c`: Used when the cell barcode is encoded as a part of the query name
(QNAME field). Split the QNAME by the delimiter specified by `-d`
and take the barcode as the value in the column specified by `-c` (0
based). For example, reads that are generated by Illumina sequencers
have FASTQ names with 7 fields that are separated by a ":", and
the cell barcode is typically added as the 8th field. The column must
exist in the QNAME of every read; this is not checked. [Default: 7].

`-t`: Used when the cell barcode is present in a SAM entry as a tag. For
example, SAM files generated by CellRanger encode the error-corrected
cell barcode in the `CB` tag. If this parameter is set, `-d` and `-c`
flags are ignored. [Default: none].

`-q`: Include only fragments for which both reads have a mapping
quality greater than or equal to the specified value. [Default: 0].

`-f`: Include only fragments for which both reads have all of the
specified flags present. For example, to include paired reads (0x1,
decimal 1) and reads that are mapped in proper pair (0x2, decimal 2),
specify the sum of these flags (1 + 2 = 3). [Default: 3].

`-F`: Include only fragments for which both reads have none of the
specified flags present. For example, to exclude PCR duplicates (0x400,
decimal 1024) and supplementary alignments (0x800, decimal 2048), specify
the sum of these flags (1024 + 2048 = 3072). The default (4 + 8 + 256 +
1024 + 2048 = 3340) excludes fragments in which either read is unmapped
(0x4), has an unmapped mate (0x8), is a secondary alignment (0x100), is a
PCR duplicate (0x400), or is a supplementary alignment (0x800).
[Default: 3340].

`-v`: Verbosity flag. Set the flag to print progress and statistics to
standard error. [Default: false].

## Input and output file description
### Description of input files
1. A paired-end aligned SAM/BAM file that has a cell barcode encoded
either in the query name or in a tag. The two reads of a fragment are
paired by their query name, so the file should contain only one
alignment for each read. Secondary and supplementary alignments, which
have the same query name as the read, should be removed beforehand (for
example, with `samtools view -F 2304`); the `-F` filter is applied only
after the reads have been paired.
1. An uncompressed TSV file with the cell barcodes in the first column
(for example, the output of [`barcode_count`](barcode_count.md)). The
counts are determined only for these barcodes.
1. An uncompressed GTF file with the genomic regions of interest. The GTF
file downloaded from [Gencode](https://www.gencodegenes.org/) can be used
directly. The `gene`, `UTR`, and `CDS` features of the GTF file are used
(the UTRs must be labeled `UTR`, as in GENCODE GTF files). The chromosome
names must match the chromosome names in the SAM/BAM file; fragments that
align to a chromosome that is not in the GTF file are not counted.
1. Optional 3-column bed files with transcription start
regions or enhancer regions (if the bed file contains more than 3
columns, they are ignored).

### Description of output files
1. `<output_prefix>_feature_counts.txt`: This file contains one row per
cell. The first column contains the cell barcode, the second column
(`count`) contains the number of fragments counted for the cell (that
can be used for normalizing the counts for each cell), and the
subsequent columns are the genomic regions. These columns contain the
number of fragments that start in each genomic region. This file has a
header line with the names of the genomic regions. The genomic region
columns are not in a fixed order, and the rows are not in the same order
as the barcode list.
1. `<output_prefix>_feature_frag_len.txt`: Similar to the above file,
but contains the mean fragment length of all the fragments that are
counted in each genomic region (0 if there are none). This file does not
have the second (`count`) column.
1. `<output_prefix>_feature_align_len.txt`: Similar to the first file,
but contains the number of bases of the fragments (from the start to the
end of each fragment, after the shift) that overlap each genomic region.
The second column (`bases`) contains the total number of fragment bases
counted for the cell.
