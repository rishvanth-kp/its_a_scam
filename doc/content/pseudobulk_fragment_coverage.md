# pseudobulk_fragment_coverage


## Description
`pseudobulk_fragment_coverage` computes the fragment coverage of groups
of cells (pseudobulks) for single cell ATAC-seq data. Each cell barcode
is assigned to a group, such as a cell type or a cluster (`-b`). The
fragments that overlap any of the regions of interest (`-r`) are kept,
and the whole of each kept fragment, including any part that lies
outside the region, is added to the coverage of the group of its cell.
The fragment positions are the alignment positions, and are not shifted
for the Tn5 insertion.

## Parameters
```
pseudobulk_fragment_coverage [options]
	-a aligned SAM/BAM file [required]
	-b barcode list file [required]
	-r regions bed file [required]
	-s distance to add to either side of region [default: 0]
	-o out file prefix [required]
	-m min. fragment length [default: 0]
	-M max. fragment length [default: 1024]
	-d name split delimiter [default: ":"]; ignored if -t is provided
	-c barcode field in name [default: 7 (0 based); ignored if -t is provided]
	-t barcode tag in SAM file [default ""]
	-q minimum mapping quality to include [default: 0]
	-f only include if all the flags are present [default: 3]
	-F only include if none of the flags are present [default: 3340]
	-v verbose [default: false]
```

`-a`: The input aligned paired-end SAM or BAM file. The cell barcode
should be present either in a SAM tag or encoded in the query name
(QNAME) field, see options `-t`, `-d`, and `-c`. [Required].

`-b`: A file with the cell barcodes and the group of each cell (see
below). Only the SAM/BAM entries that match a barcode in this file are
processed. [Required].

`-r`: A bed file with the regions of interest. Only the fragments that
overlap at least one region are included. [Required].

`-s`: Number of bases to add to the ends of each region in the above bed
file. This parameter is useful to include the fragments flanking a
region of interest. `-s` must not be larger than the start of any
region; this is not checked. [Default: 0].

`-o`: Output file prefix. [Required].

`-m`: Minimum fragment length to include. Fragments that have a length
lower than this value are ignored. The fragment length is the distance
between the outermost alignment positions of the two reads.
[Default: 0].

`-M`: Maximum fragment length to include. Fragments that have a length
higher than this value are ignored. [Default: 1024].

`-d`: Used when the cell barcode is encoded as a part of the query name
(QNAME field). Split the QNAME by the specified delimiter. [Default:
":"].

`-c`: Used when the cell barcode is encoded as a part of the query name
(QNAME field). Split the QNAME by the delimiter specified by `-d`
and take the barcode as the value in the column specified by `-c` (0
based). For example, reads that are generated by Illumina sequencers
have FASTQ names with 7 fields that are separated by a ":", and
the cell barcode is typically added as the 8th field. The column must
exist in the QNAME of every read; this is not checked. [Default: 7].

`-t`: Used when the cell barcode is present in a SAM entry as a tag. For
example, SAM files generated by CellRanger encode the error-corrected
cell barcode in the `CB` tag. If this parameter is set, `-d` and `-c`
flags are ignored. [Default: none].

`-q`: Include only fragments for which both reads have a mapping
quality greater than or equal to the specified value. [Default: 0].

`-f`: Include only fragments for which both reads have all of the
specified flags present. For example, to include paired reads (0x1,
decimal 1) and reads that are mapped in proper pair (0x2, decimal 2),
specify the sum of these flags (1 + 2 = 3). [Default: 3].

`-F`: Include only fragments for which both reads have none of the
specified flags present. For example, to exclude PCR duplicates (0x400,
decimal 1024) and supplementary alignments (0x800, decimal 2048), specify
the sum of these flags (1024 + 2048 = 3072). The default (4 + 8 + 256 +
1024 + 2048 = 3340) excludes fragments in which either read is unmapped
(0x4), has an unmapped mate (0x8), is a secondary alignment (0x100), is a
PCR duplicate (0x400), or is a supplementary alignment (0x800).
[Default: 3340].

`-v`: Verbosity flag. Set the flag to print progress and statistics to
standard error. [Default: false].

## Input and output file description
### Description of input files
1. A paired-end aligned SAM/BAM file that has a cell barcode encoded
either in the query name or in a tag. The two reads of a fragment are
paired by their query name, so the file should contain only one
alignment for each read. Secondary and supplementary alignments, which
have the same query name as the read, should be removed beforehand (for
example, with `samtools view -F 2304`); the `-F` filter is applied only
after the reads have been paired.
2. A bed file (the first 3 columns are used) that contains the regions
of interest.
3. An uncompressed 2-column TSV file without a header, with the cell
barcode in the first column and the name of its group in the second
column. Every line must have a group; this is not checked. There can be
at most 256 groups; this is not checked, and with more groups, some
groups are merged.

### Description of output files
1. `<output_prefix>_pseudobulk_fragment_coverage.txt`: The coverage of
each group. The first 3 columns contain the chromosome name, start, and
end of each region (0-based start, and the end is not included), and the
subsequent columns are the groups, in the order in which they first
appear in the barcode file. Each value is the number of fragments of the
group that cover the region. Only the positions that are covered by at
least one included fragment are listed, and adjacent positions that have
the same coverage may be merged into a single region. This file has a
header line with the column names `chrom`, `start`, and `end`, followed
by the group names.
2. `<output_prefix>_pseudobulk_fragment_counts.txt`: One row per group,
with the group name, the number of included fragments (`frag_count`),
and the sum of their lengths (`base_count`). This file has a header
line.
